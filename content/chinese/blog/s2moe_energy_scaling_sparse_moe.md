# 随着模型扩展而增长的效率优势：Top-1 Spiking MoE 中的每令牌能量

**摘要**

- Top-1 路由每个令牌运行**一个**专家，与池大小无关，因此前馈成本**在专家数量上保持恒定**，而参数匹配的密集模型的成本线性增长。添加专家会*降低*每令牌能量。
- 在 H100 上测量三个模型规模：在 1B 参数处的 8 / 32 / 64 个专家时，**1.46× → 3.07× → 5.08×** 每令牌更少能量，相对于密集基线和参数匹配的 Transformer。
- 在 8 个专家处**根本没有能量优势**。该体系很重要，本文以此开头。
- 节省不是免费的--它需要分组 GEMM 内核。没有它，稀疏模型在每个专家数量处都*比密集*慢。
- 在 ~128 个专家之上，FLOP 代理和测量的焦耳**发散**。FLOP 停止是代理，开始讲述一个故事。

代码、内核和完整实验日志：**[github.com/JustinGuese/SpikingBrain2.0-s2moe](https://github.com/JustinGuese/SpikingBrain2.0-s2moe)**。

这是[这个相同项目中的*质量*声称如何在更长的训练预算下反转的帖子的后续](./budget-dependent-benchmarking-sparse-moe)。那一个的简短版本：学到的声称移动了，形状确定的没有。本文涉及形状确定的。

## 1. 为什么优势随专家数量增长

算术足够简单，可以在一个段落中说明，这是信任它的主要原因。

使用 Top-1 路由的[混合专家](https://arxiv.org/abs/2101.03961)层将每个令牌发送到恰好一个隐宽度为 `d_hidden` 的专家。因此其前馈每令牌成本**独立于 `n_experts`** --64 个专家每令牌花费与 8 个相同。参数匹配的密集模型必须在某处花费这些参数，所以其前馈宽度为 `d_ff = n_experts · d_hidden`，其每令牌成本在同一变量中**线性**增长。

因此它们之间的比率在专家数量中线性增长。您添加的每个专家都会使基线更昂贵，并将稀疏模型留在原地。

这不是学到的属性。这是张量形状的结果，这就是为什么它在随机权重下成立、在预算扫描中存活，以及不关心您训练的是哪个语料库。

![破碎的权衡：质量对活跃计算](paper/figures/fig2_broken_tradeoff.png)

## 2. 它不起作用的体系（Exp 17）

在好数字之前值得说明，因为它限制了它们。

在**8 个专家和 25M 参数处，没有能量优势。**测量（Exp 17）发现：

- 始终开启序列混合器主导前向传递。前馈仅占稀疏模型计算的约 16%，因此将其减少 8 倍仅约减半总 FLOP。
- **GPU 功率是架构平坦的** --跨所有测试变体约 52–57 W。在这个硬件上，"每令牌能量"简化为每令牌延迟。没有功率下降可收获。
- 使用天真的每专家 Python 分发循环，稀疏模型*比密集*慢。FLOP 节省被内核启动开销消耗。

那时的结论是能量轴已死。不过它命名了自己的逃生路线：能量优势只有在更大的专家数量处才可能想象，那时前馈会在*密集*传递中重新占据主导地位，而且只有在配备真正的稀疏内核时才可能实现。

这两个条件都证明是可满足的。

## 3. 它转向的地方（Exp 22）

保持 `d_model`、`d_hidden` 和深度固定并扫描专家数量，在持续推理循环上进行空闲减去的功率积分：

| 专家 | 参数   | 分组 MoE ktok/s | 密集 ktok/s | **能量× 对比密集** | 对比 Transformer |
| ---- | ------ | --------------- | ----------- | ------------------ | ---------------- |
| 8    | 27.3M  | 101.5           | 82.3        | **1.31×**          | 1.16× (≈ 打平)   |
| 32   | 77.8M  | 78.4            | 33.8        | **2.50×**          | 1.03×            |
| 64   | 144.9M | 71.9            | 18.1        | **3.99×**          | 0.97×            |

密集模型的前馈份额上升 61% → 86% → 92%，而稀疏模型的保持平坦在约 0.022 GFLOP/令牌。参数匹配的 Transformer 从扫描中**无获益**（≈1.0× 密集始终），因为它没有稀疏性可利用--因此缺口对主导架构从 8 个专家处的平局打开到 64 个处的约 4×。

功率始终保持平坦（约 54–57 W 分组对比约 57–60 W 密集），确认这是吞吐量优势而非功耗优势。该区别很重要，我稍后会回到它。

## 4. 内核负重（Exp 13、Exp 24）

更少的 FLOP 不会自动意味着更少能量。某些事物必须将一个转换为另一个。

天真的实现在 Python 循环中分发专家--每个专家一次迭代和一次内核启动。该开销按专家固定，因此它增长完全与节省相同的速度。**循环分发在测试的每个专家数量处都比密集*慢*** （相对延迟 0.72–0.78×）。隔离测量，"高效"的架构是回归。

修复是排序的、无损分组 GEMM：按分配的专家对令牌排序到连续段，构建累积偏移，并在一次启动中对所有段发出两个分组矩阵乘法。零令牌专家变成零宽度段--0 FLOP，无填充，因此条件执行被保留而非伪造。

**推理（Exp 13）：**

| 专家 | 循环 tok/s | 分组 tok/s | 加速      | 最大绝对 Δ logits |
| ---- | ---------- | ---------- | --------- | ----------------- |
| 8    | 60,061     | 88,963     | **1.48×** | 0.00e+00          |
| 16   | 41,049     | 86,245     | **2.10×** | 0.00e+00          |
| 32   | 24,774     | 81,594     | **3.29×** | 0.00e+00          |

分组吞吐量保持大约平坦（89k → 86k → 82k），而循环崩溃（60k → 41k → 25k）。输出是**位相同的** --零 logit 差，零 argmax 翻转。加速是纯开销去除，不是近似。

**训练（Exp 24）：**同一内核通过显式反向使其能够自动微分，在 8 / 16 / 32 / 64 个专家处提供**1.26× / 1.61× / 2.59× / 4.51×** 更快的训练步骤，`w_in` 和 `w_out` 梯度**与循环位相同**，且 Δloss = 0。那去除了整个故事的"仅推理"星号。

如果您从这篇文章获取一个工程要点：**没有其内核的高效架构是*更慢的*架构。** FLOP 计数是一张本票；内核是它是否清除。

## 5. 它缩放（Exp 27）

H100 上的九个点--三个模型规模 × 三个专家数--每个基准四个形状匹配变体。随机权重、仅推理，因此测量是形状确定的且不需要训练。净 mJ/令牌、稀疏 / 密集 / Transformer，MoE 对密集比率加粗：

| 规模 | 8 专家                           | 32 专家                          | 64 专家                           |
| ---- | -------------------------------- | -------------------------------- | --------------------------------- |
| 25M  | 0.46 / 0.77 / 0.75 (**1.67×**)   | 0.49 / 1.98 / 1.99 (**4.08×**)   | 0.51 / 3.65 / 3.56 (**7.13×**)    |
| 350M | 2.73 / 4.26 / 3.84 (**1.56×**)   | 2.92 / 10.31 / 9.40 (**3.53×**)  | 3.11 / 17.80 / 16.64 (**5.72×**)  |
| 1B   | 9.12 / 13.35 / 11.65 (**1.46×**) | 9.52 / 29.25 / 28.17 (**3.07×**) | 10.32 / 52.38 / 50.56 (**5.08×**) |

跨越 1B 行读取：稀疏能量随专家 8× 缩放进展 9.1 → 9.5 → 10.3--基本平坦，如 §1 中的算术预测。密集进展 13 → 29 → 52。

![跨模型规模和专家数量的能量](paper/figures/fig1_energy_scaling.png)

与这个数字相伴的两个诚实观察。首先，分组内核**移植到 Hopper（sm_90）** 干净地，被开发于 Blackwell（sm_120）--它不是一个架构的伪影。其次，**比例随模型规模在固定专家数处软化**（64 个专家处 7.1× → 5.7× → 5.1×）因为始终开启序列混合器在 `d_model` 增长时取更大的绝对份额。杠杆是专家数，不是模型大小。说"1B 处 5×"而不提及该警告会通过省略过度销售。

## 6. FLOP 停止预测焦耳的地方（Exp 48、Exp 50）

这是应该使系统读者相信其余部分的部分。

有两种不同的方式来"添加专家"，它们在相反的方向上表现。

**固定 `d_hidden`（容量缩放）**是 §3 和 §5：更多专家意味着更大的密集基线，因此能量优势增长。

**固定总预算（粒度）**保持 `n_experts · d_hidden` 恒定并使每个专家更小。FLOP 代理喜欢这个--精度每单位活跃计算单调攀升**23.4× → 35.0× → 46.3× → 53.0×**在 32 / 64 / 128 / 256 个专家处（Exp 50，修复了清除搅动混淆）。

测量的能量不同意。以下是 FLOP 代理和瓦特表并排，两者来自同一屏幕（Exp 48--其代理数字运行略高于上面修复搅动的 Exp 50 数字，但趋势是重要的）：

| 专家 | 精度/活跃计算（FLOP 代理） | 测量 mJ/令牌 | 对比密集能量   |
| ---- | -------------------------- | ------------ | -------------- |
| 64   | 34.8×                      | 0.803        | **2.21×** 更少 |
| 128  | 50.9×                      | 0.807        | **2.19×** 更少 |
| 256  | 60.2×                      | 0.954        | **1.83×** 更少 |

**mJ/令牌上升而 FLOP 代理攀升。**许多微小专家（宽度 256 → 64）上的每组启动开销吃掉节省。在能量感知决策规则下--仅当质量改进*和*能量边缘持平时才接受更改--64 和 128 通过，**256 被拒绝**：它花费真实焦耳来购买代理数字。

所以**~128 个专家是实现的甜蜜点**，"FLOP 不是焦耳"获得实际坐标而非警告。缝隙是分组内核开销而非任何基本的东西--平铺感知内核可以推动膝盖--但直到那被写出，诚实的声明是内核条件。

![粒度：FLOP 代理和测量能量在 ~128 个专家上方发散](paper/figures/fig6_granularity_law.png)

## 7. Spiking 实际购买什么（Exp 51、Exp 60）

模型使用二进制[尖刺](https://open-neuromorphic.org/)激活--泄漏积分和火灾神经元发出 0 或 1 而非浮点。明显的审查员问题是这是否损失精度。两个对照端到端回答它。

将二进制隐藏尖刺替换为等 FLOP 处分级 SiLU（Exp 51）：57.10 对比 57.44 困惑--**尖刺是 0.6% 更好**，语法打平。然后移除*整个*尖刺装置包括入门门（Exp 60）：**56.5 对比 57.10** 困惑，BLiMP **0.691 对比 0.691** --完全相同。

完整会计因此是：**尖刺总共花费约 1% 质量且是语法中立的。**其值是二进制激活使专家无乘法且给予真正零 FLOP 条件执行--未被触达或未激发的专家什么都不运行。这是事件驱动硅的硬件兼容性论证，不是精度论证，而在审查员之前声明它不花费任何代价。

## 8. 诚实范围

在引用上面任何数字前阅读这个。

**能量基准仅是推理且随机权重。**它测量计算的形状，不是训练部署。这使其保守且可重现，但这不是真实工作负载上的服务基准。

**在功率平坦 GPU 上，"每令牌能量"真正是活跃 FLOP 在吞吐量上。**测量的功率在所有测试架构中变化约 52–60 W，因此优势是延迟驱动的。可防御的框架是**服务成本和每美元令牌**，不是原始焦耳。真正的事件驱动能量会计需要神经形态硬件--[SpiNNaker2](https://spinncloud.com/) 或 [Loihi 2](https://www.intel.com/content/www/us/en/research/neuromorphic-computing.html) --该项目未测量。这是最大的一个未解决问题。

**批量服务侵蚀每令牌稀疏性（Exp 65）。**服务器实际要承担成本的，是批次内被触及专家的并集，而这个比例迅速崩溃：**批 1 处 96.9% 联合稀疏，批 32 处 39.7%，批 64 处 14.1%。**在 64 个并发解码步骤，86% 的池被触及。这与已将上下文稀疏技巧排除在生产服务堆栈外的相同限制（参考 [Dejavu](https://arxiv.org/abs/2310.17157)），这就是为什么每令牌优势最好被读作边缘和单流解码属性。

修复它的尝试失败了它自己的杀死门（Exp 66）：分组协议路由目标意味着将批路由浓缩到更少专家组产生批 32 联合稀疏为 **0.371** 对比无修改基线的 **0.397** --整个曲线叠加。辅助项简直被负载均衡损失压倒。报告而非埋藏，用于[伴侣文章中的原因](./budget-dependent-benchmarking-sparse-moe)。

**这里一切都是 2.5M–145M 参数**用于训练结果，能量曲线具体化到 1B 维度。它不是边界规模声称。

## 9. 什么成立

剥去上面每个警告存活的：

- Top-1 路由使前馈成本**在专家数量上恒定**；密集基线线性增长。这是算术，不是发现。
- 在 H100 上测量，这在 1B 参数处产生**32 个专家处 3.07×** 和 **64 个专家处 5.08×**每令牌更少能量，对比密集模型和参数匹配 Transformer。
- **分组 GEMM 内核是使其真实的东西** --位精确，且在高专家数处值得 3.29× 推理和 4.51× 训练。没有它，这都不存在。
- **在固定预算处 ~128 个专家之上，测量能量和 FLOP 代理发散。**信任焦耳。
- **尖刺花费 ~1% 质量**且购买神经形态兼容性，不是精度。

## 常见问题

**Q: 混合专家在推理处实际保存能量吗？**
这完全取决于专家数和内核。在 8 个专家处，测量这里，没有优势--始终开启混合器占主导且分发开销吃掉节省。在 32–64 个专家处带分组 GEMM 内核，它是 1B 参数处 3–5× 每令牌更少能量。

**Q: 为什么优势随着您添加专家而增长？**
无论专家池有多大，Top-1 路由都为每个令牌运行一个专家，因此稀疏成本在专家数中保持平坦。参数匹配密集模型相同参数预算线性增长前馈宽度。比率因此线性增长。

**Q: 更少 FLOP 是相同于更少能量吗？**
不是在固定预算处 ~128 个专家之上。从 128 个专家到 256 个专家，测量的 mJ/令牌从 0.807 升至 0.954，而 FLOP 基准指标却仍在持续改善--这是许多微小专家上的每组启动开销所致。测量焦耳。

**Q: 这在批量服务下成立吗？**
部分。每令牌联合稀疏从批 1 处 96.9% 下降到批 32 处 39.7%。每令牌能量优势对单流和边缘解码最强；批量服务仅恢复一部分。

**Q: 尖刺激活贡献什么？**
大约 1% 质量成本、语法中立。效益是无乘法专家和真正零 FLOP 条件执行，对事件驱动神经形态硬件更重要而不是 GPU 精度。

## 重现它

用 [uv](https://docs.astral.sh/uv/) 在 [PyTorch](https://pytorch.org/) 上管理：

```bash
git clone https://github.com/JustinGuese/SpikingBrain2.0-s2moe
uv sync

# 实时 CUDA 功率 + 延迟，随机权重（形状确定）
uv run python bench_energy.py --n-experts 64 --d-model 512 --d-hidden 512 \
    --n-layers 4 --batch 16 --seq 256

# 内核等价 + 加速，推理和训练
uv run python bench_dispatch.py
uv run python bench_train_dispatch.py
```

# 当我训练更长时我的效率优势反转：关于预算相关基准的一个说明

**摘要**

- 一个 Top-1 稀疏[混合专家](https://arxiv.org/abs/2101.03961)模型击败参数匹配的密集基线**−2.4% ± 1.1% 验证困惑，3/3 种子，配对_t_ ≈ 3.8（p ≈ 0.03）**。干净结果。看起来可发布。
- 三个分离检查撕裂了它：一个**学习率计划**变化、一个**正确调谐的基线**，和一个**4× 更长的训练预算**。
- 在 4× 预算上困难网络文本，符号**反转**：密集赢得**+2.4% ± 0.8%**，也 3/3 种子。
- 一般教训：在[Chinchilla 最优](https://arxiv.org/abs/2203.15556)预算远下方，效率比较会系统性地让活跃计算更少的模型显得更好。大多数论文不曾运行较长预算。
- 存活下来的是那条_不能_反转的轴，因为它根本不是学出来的。更多在结束处，和在[能量缩放伴侣文章](./sparse-moe-energy-scaling-per-token)。

下面的所有数字来自公共实验日志：**[github.com/JustinGuese/SpikingBrain2.0-s2moe](https://github.com/JustinGuese/SpikingBrain2.0-s2moe)**（`EXPERIMENTS.md`，66 条目，最新优先）。这篇文章中的每个声称引用您可以去读的实验号。

## 1. 看起来完成的结果

架构是 S²-MoE：一个稀疏尖刺混合专家语言模型。这篇文章的相关细节只是它将每个令牌路由到`n`之一，因此它相对于参数数量相同的密集模型执行大约`1/n`的前馈计算。

在[TinyStories](https://arxiv.org/abs/2305.07759)上 25M 参数，字节对标记化，6000 步，三个种子作为隔离进程运行（**Exp 12**）：

| 指标（25M，6000 步，3 种子）                       | S²-MoE                   | 密集         |
| ------------------------------------------------------- | ------------------------ | ------------- |
| 验证困惑                                                   | **5.63 ± 0.09**          | 5.77 ± 0.03   |
| 配对间隙（MoE − 密集）                                | **−2.4% ± 1.1%**         | —             |
| 每种子间隙                                            | −1.2% / −2.6% / −3.3%    | 3/3 倾向 MoE |
| 每活跃计算精度                             | **8.20× ± 0.10**         | 1×            |
| 活跃 FFN 计算分数                             | 0.125（精确）            | 1.000         |
| [BLiMP](https://arxiv.org/abs/1912.00582) 语法增量 | +0.003 ± 0.015（中立） | —             |

从表面上看，这不是一个弱结果。它是配对的（相同种子为两个臂固定数据顺序和初始化），每个种子同意符号，密集基线有接近零种子方差，语法探测说稀疏不花费语法。更长的训练使效果_更大_，不是更小——通常一个好信号。

这一点的诱惑是停止测量。

## 2. 结果分崩离析的三种方式

### 2.1 计划做了工作（Exp 15）

上面每个结果使用**平的学习率** ——项目默认，最初为[门线性注意](https://arxiv.org/abs/2312.06635)混合器调谐。这对单一架构而言是站得住脚的选择，但用于比较就说不通了。

在[FineWeb-Edu](https://huggingface.co/datasets/HuggingFaceFW/fineweb-edu)上为每个分支采用相同的现代化计划重新运行——线性热身然后余弦衰减到 10%，每个模型在其自己调谐峰值 LR：

| 模型（25M，FineWeb-Edu，6000 步） | Val ppl   | BLiMP | 活跃 FFN 计算 |
| ------------------------------------ | --------- | ----- | ------------------ |
| GLA 密集                            | **51.37** | 0.713 | 1.000              |
| Transformer                          | **51.17** | 0.704 | 1.000              |
| S²-MoE                               | 56.90     | 0.694 | **0.125**          |

MoE 从平的 LR 下**8% 更好**到热身+余弦下**11% 更坏**。机制在增量中可见：密集模型从合适的计划获益**25%**（68.5 → 51.4）；MoE 仅获益**9.5%**（62.9 → 56.9）。密集模型每步更新每个参数，因此它可以利用余弦衰减的微调尾。Top-1 MoE 每令牌更新大约`1/n`其专家池，因此每个专家只看到数据的一部分，并从这条长尾中兑现少得多的收益。

平 LR 协议不是中立的。它妨碍从好计划获益最多的臂。

### 2.2 您未调谐的基线不是基线（Exp 15，运行 #1）

第一次尝试加入真正的 softmax 注意力 Transformer 对照组时，直接沿用了为 GLA 调好的设置：固定 `lr=3e-3`，无热身。它从不训练——验证困惑**380**，对比密集 GLA 模型的 68。

那次运行制造出一个"S²-MoE 比 Transformer 好 48 倍"的头条数字。

该数字没有被删除，而是作为教训被记录了下来。它测定的是一个破碎的对照组，不是一个好模型。简短的诊断确认一个合适配置的 Transformer（`lr=6e-4`，热身，余弦）训练好并降落在 51.17 ——即，它_击败_MoE。

这种故障模式很容易陷入，却要到发表之后才能发现，代价高昂。注意远比线性递推混合器 LR 敏感；在比较中重用一个架构的超参数为您希望的任何结果制造。**为每个臂报告调谐预算和最终 LR，包括您试图击败的那些。**

### 2.3 预算隐藏了间隙（Exp 44 → Exp 47）

三个中最转移的。相同锁定配置——32 专家，始终开启共享核心，自蒸馏，余弦计划，分组 GEMM 分发——在 FineWeb-Edu 上跨训练预算扫描：

| 训练步骤 | MoE 对比密集                              | 裁决             |
| -------------- | ----------------------------------------- | ------------------- |
| 6,000          | **−5.15% ± 0.11%**（3/3 种子，_t_ ≈ −81） | MoE 明确赢得 |
| 12,000         | ≈ 平价                                  | —                   |
| 24,000         | **+2.4% ± 0.8%**（3/3 种子）              | 密集赢得          |

干净的单调交叉，在端点跨三个种子确认，不是幸运的抽签。6k 结果有_t_统计−81。反思起来，它其实是一个关于欠训练的声明，而不是关于架构的声明。

## 3. 泛化

这部分是值得带到其他项目中的内容。

**在计算最优预算远下方运行的比较，会系统性地让活跃计算更少的模型显得更好。**两个臂都欠培训；密集模型拥有更多尚未兑现的容量；稀疏模型更接近其自己天花板，因为每个专家已经看到了其狭窄数据片。最终将分离他们的间隙尚未打开。在那里测量您测量交叉区，不渐近线。

同一组扫描还得出了两个推论。

**交叉点是语料库的属性，不是架构。**在两个语料库上运行相同 24k 步配置（**Exp 47**）：

| 语料库      | 单字母熵  | MoE 对比密集在 24k                | BLiMP 增量 |
| ----------- | ---------------- | ---------------------------------- | ----------- |
| TinyStories | 8.39 bits/令牌  | **−2.6% ± 0.3%**（3/3，MoE 赢得）   | +0.039      |
| FineWeb-Edu | 10.50 bits/令牌 | **+2.4% ± 0.8%**（3/3，密集赢得） | −0.007      |

符号只随语料库变化而翻转。在结构化文本上 MoE 赢得的幅度随预算窄化（−4.4% 在 6k → −2.6% 在 24k）但不曾交叉零。在多样化的网络文本上，它会交叉并保持反转。所以"稀疏是否有损质量？"并没有一个不依赖预算和语料库的统一答案——意思是任何论文若只报告这类表面上的单点结果，报告的只是一个坐标，不是结论。

**和那上的诚实限制（Exp 53）：**_方向_法则成立，但_量_是不从这些运行中拟合的。仅有两个语料库熵点，计划、蒸馏，和预算是相似幅度的共线混淆因子——每专家令牌计数不曾正确排序符号。拟合预测曲线到那将产生一个有体面外观 R² 的非识别表面。日志由此指明的后续工作已经明确（冻结一个协议、增加≥2 个语料库、运行 `n × 语料库` 网格），而不是靠近似。

### 四项检查清单

1. **至少运行两个预算**，理想地 4× 分开。如果您的声称仅在一个存在，它是关于该预算的声称。
2. **至少运行两个不同难度的语料库。**玩具语料库不是困难语料库的小版本；他们改变符号这里。
3. **每个基线单独调谐并报告其 LR。**跨架构一个计划是天平上的一个拇指。
4. **报告配对每种子符号，不只是均值 ± std。**"3/3 个种子一致"和"均值为负"是两种不同的声称，后者读起来的说服力其实比实际更弱。

## 4. 捕捉它的过程

这一切都不是运气。做法是**在一次昂贵的运行之前，先预先设定一个数值杀死门**，然后当它失败时尊重它。九个想法都已经死在了自己的杀死门下。以下是一个代表性样本：

| 想法                                                            | 为什么它死亡                                                    | Exp |
| --------------------------------------------------------------- | -------------------------------------------------------------- | --- |
| 混合器写门                                                | 跳过对递推状态的写爆炸困惑 ~7×  | 32  |
| [混合深度](https://arxiv.org/abs/2404.02258) 停止门 | −1.9% 质量；实现 ~16% 稀疏对比 50% 目标          | 42  |
| 神经调制路由                                         | 无质量增益；路由级别修复继续失败              | 34  |
| 树突专家                                               | 门安定 38% 打开——变成了稀疏化器，+1.05% 更坏      | 46  |
| 临界设置点                                            | 73.03 对比配对 72.86 基线——门未达到                | 62  |
| 事件驱动 FFN                                                | 连续令牌余弦 0.561 对比 0.7 门槛                    | 64  |
| 秩 1 残基修正                                      | 惯性：活跃计算未改变，阈值扫描未移动 | 66  |

四个门想法分享一个形状，并且它是整个日志中最有用的模式：**任何可学习门优化器被允许关闭，它关闭。**每个被设计添加条件容量；每个都被当作现有机制之上的第二个稀疏化器来使用，并额外花费 1–2% 的质量。

两个想法不是小的——他们是项目的推销区别，他们到_干净控制_而非坏数字死亡：

- **连续适应（Exp 60、61）。**声称：稀疏模型忘记更少，因为增长隔离新域到新专家。Exp 60 增加一个睡眠关闭控制，其着陆相同到睡眠打开——所以机制不做工作。Exp 61 然后_强制_隔离与路由锁：新域令牌命中新专家独占（测定溯源分数**1.00**，零流失）。保留仍未移动——**116.7 对比 117.3**。遗忘存在于始终开启的密集成分中，稀疏部分无法对其提供保护。伪造，不是未调谐。
- **"渐进增长是特殊的"（Exp 59）。**一个单发块[上升](https://arxiv.org/abs/2212.05055)得分**73.37**，坐内渐进增长臂的两个种子传播 72.94–73.44。更早的"渐进赢得"结果来自一个已漏露的控制，已静静增长所有沿途。

这个纪律的成本论证是**Exp 64**。事件驱动想法是吸引的并将花费数周构建。门是一个测量：连续令牌激活是否被关联足够跳过重计算？均值余弦相似**0.561**对比一个预先商定的 0.7 门槛——而且它还会随深度_下降_。总成本：一个基准脚本和零训练运行。

相同的逻辑运行便宜的屏幕：一个种子在半步回答"这移动质量吗？"，和只有存活者赚三个种子在完全长度。一个说"否"的 $0.30 屏幕值得超过一周在一个未验证杠杆上花费。

## 5. 什么实际存活了

一个段，无论证。

声称通过每个计划改变、每个语料库，和 4× 预算扫描成立是那个从不在第一个地方学到的：**精度每单位活跃前馈计算保留在 ~21×跨 6k、12k，和 24k 步在两个语料库。**它是形状确定的——Top-1 路由执行一个专家不管池大小的结果——因此没有机制通过这个更多训练可能反转它。那是精确为什么它存活当质量声称不。一个不能在预算下移动的数字是一个从不依赖欠培训的数字。

这个轴是下一篇的主题：[能量每令牌如何随专家计数缩放，其中测量曲线停止与 FLOP 计数同意，和尖刺实际购买什么](./sparse-moe-energy-scaling-per-token)。

## 常见问题

**Q: 为什么 MoE 击败小规模密集但在大规模失败？**
两个模型都欠培训。密集模型每步更新每个参数并保留改进；Top-1 MoE 每令牌更新 ~1/n 其专家池，因此它更早接近其天花板。在低预算下，密集模型还未兑现其容量，所以比较偏向稀疏模型。看 Exp 44 和 47。

**Q: 那意思稀疏模型更坏吗？**
否——它意思质量比较是预算和语料库依赖的，_效率_比较不是。在结构化文本稀疏赢得存活 4× 预算增加；在多样网络文本它反转。活跃计算优势保留随处。

**Q: 我在声称效率赢之前应该测试多少训练预算？**
最少两个，理想地在至少两个不同难度语料库上 4× 分开。在这个项目符号在一个语料库之间 6k 和 24k 步翻转和不另一个。

**Q: 什么是杀死门？**
一个数值阈值前写入贵运行，定义什么结果将杀死想法。Exp 64 杀死多周方向与单个基准脚本因为门在前面被设置。

**Q: 哪里我可以看原始实验日志？**
`EXPERIMENTS.md`在[GitHub 存储库](https://github.com/JustinGuese/SpikingBrain2.0-s2moe)——66 条目，每个与假设 → 方法 → 观察 → 结果，包括一切失败。

## 重现它

项目用[uv](https://docs.astral.sh/uv/)在[PyTorch](https://pytorch.org/)管理：

```bash
git clone https://github.com/JustinGuese/SpikingBrain2.0-s2moe
uv sync
uv run python phase0.py    # regression gate, expects: PHASE 0: PASS

# 头对头：MoE + 参数匹配密集控制，相同预算
uv run python train_lm.py --tokenizer bpe --scale 25m \
    --d-model 512 --d-hidden 512 --n-layers 4 --n-experts 32 \
    --d-shared 256 --distill --dispatch grouped --blimp --n-seeds 3
```
